# 本番公開のチェックリスト

クローズドテスト（12人以上・14日間連続）が終わってから、Google Play の本番に出すまでの手順です。
Play Console の画面名は変わることがあります。実際の表示に合わせて読み替えてください。
済んだら `[x]` にします。

## 1. 本番へのアクセスを申請する
- [ ] クローズドテストの条件を確かめる：12人以上が、**14日間続けて**参加していたか（途中で抜けた人がいないか）
- [ ] ダッシュボードの「本番環境へのアクセスを申請」を押す
- [ ] アンケートに答える
  - テスターを集めた方法
  - テスターから得た意見と、それをどう直したか（例：0.3.0 で Play ゲーム対応・ペナルティの廃止・点数表・スタート画面）
  - 本番に出せると考える根拠
- [ ] 審査の結果を待つ（数日〜1週間ほど）。承認されるまで本番のリリースは作れない

## 2. 本番用のビルドを作る（手元で）
- [ ] **versionCode を上げる**：クローズドテストに上げた番号（0.3.0 = 300）より大きくする。`package.json` の version を 0.3.1 にすると 301
  - 計算：major×10000 + minor×100 + patch（`android/app/build.gradle`）
- [ ] `npm ci` → **`npm run android:release`** → `npm run android:open`
  - `android:release` は `.env.release` の本番の広告ユニット ID を読む。**開発用の `npm run android` で作ったものは、テスト広告のままなので本番に上げない**
- [ ] Android Studio：Build → Generate Signed App Bundle で、署名付き AAB を作る
- [ ] 作った AAB の versionCode が、上げる予定の番号になっているか確かめる

## 3. ストアの掲載情報
`store/listing.md` の文をそのまま貼る。
- [ ] アプリ名・簡単な説明・詳しい説明
- [ ] アイコン（`store/icon-512.png`）、フィーチャーグラフィック（`store/feature-graphic.png`）
- [ ] スクリーンショット 6枚（`store/screenshots/1-core.png` 〜 `6-survive.png`）。今のゲーム画面で撮り直し済み
- [ ] 動画の URL：`store/promo/` の動画は **今の画面とずれている**（BET・点数表・スタート画面など）。出すなら撮り直す。出さないなら空欄でよい。「Google Play でテスト中」の文が入ったままの動画は使わない
- [ ] カテゴリ（ゲーム／ボード）、メールアドレス、ウェブサイト
- [ ] 連絡先の住所：**本名と現住所のまま出る**ことを承知しておく（変える場合は、公開前でも後でも開発者アカウントの設定から変更できる）

## 4. アプリのコンテンツ（ポリシーとプログラム）
- [ ] プライバシーポリシーの URL（https://konja9.github.io/privacy.html）が開ける
- [ ] **プライバシーポリシーに Play ゲームの段落を足す**（文は `store/play-games.md` の「7. 公開の前に直すもの」。別のリポジトリ `konja9.github.io`）
- [ ] **データセーフティ**を最新にする
  - 広告（AdMob）：広告 ID、端末や利用状況のデータ
  - アプリ内課金（広告削除）
  - Play ゲーム：プレイヤー ID、クラウドセーブ（ゲームの進み具合）
- [ ] 広告：「広告を含む」を選ぶ
- [ ] コンテンツのレーティング：質問票に答え直す（ギャンブルに似た演出があるが、現金の賭けも換金もない）
- [ ] 対象年齢、ニュースアプリ、政府アプリなどの申告
- [ ] アプリ内課金の商品（広告削除）が「有効」になっている

## 5. Play ゲームの公開
- [ ] 実績15個・ランキング2つの名前・説明・ポイントを最終確認する（**公開すると消せない**）
- [ ] 認証情報（OAuth）に、**アプリ署名鍵の SHA-1**（Play Console → アプリの完全性）が入っている
- [ ] Play ゲームの構成（プロジェクト）を「公開」する。公開前はテスターしか使えない

## 6. 本番リリースを作る
- [ ] 本番トラックで新しいリリースを作り、AAB を上げる
- [ ] リリースノートを貼る（`store/release-notes-0.3.0.md` の「新機能」のブロック。500文字以内）
- [ ] 公開の割合：最初は 20% などの**段階的公開**にして、クラッシュや ANR を見てから全員に広げる方法もある
- [ ] 審査に出す

## 7. 公開したあと
- [ ] **AdMob**：アプリを Play ストアのアプリと関連付ける（広告がきちんと配信されるようになる）
- [ ] 本番の広告が出るか、同意画面（UMP）が出るかを確かめる。**自分で本番の広告をタップしない**（アカウント停止の対象）
- [ ] Play Console の「Android vitals」でクラッシュ・ANR を見る
- [ ] レビューに返信する
- [ ] 実績・ランキング・クラウドセーブが、本番のアプリで動くか確かめる
